# Second Step

In this step, we created a central dashboard to access all the web applications and services deployed in the homelab.

The dashboard is available through:

`dashboard.home`

Each service is represented by a card containing its name, description and URL. This makes it easier to access the different applications without remembering every address.

## Web structure

The frontend was separated into three files:

```text
web/
├── index.html
├── styles.css
└── app.js

## Adding a new service card

To add a new card to the dashboard, a new object must be added to the `services` array located in:

```text
apps/homelab-dashboard/web/app.js
```

Example:

```javascript
const services = [
  {
    name: "Pi-hole",
    // Existing Pi-hole configuration
  },
  {
    name: "Web Demo",
    // Existing Web Demo configuration
  },
  {
    name: "Grafana",
    description: "Cluster metrics and monitoring dashboards.",
    url: "http://grafana.home",
    displayUrl: "grafana.home",
    tag: "Monitoring",
    icon: "chart-no-axes-combined",
    color: "#f59e0b",
    glow: "rgba(245, 158, 11, 0.16)"
  }
];
```

Each property controls a part of the card:

- `name`: service name.
- `description`: short description displayed on the card.
- `url`: destination opened when clicking the card.
- `displayUrl`: URL displayed at the bottom of the card.
- `tag`: service category.
- `icon`: icon name from Lucide.
- `color`: main accent color.
- `glow`: card hover glow color.

After modifying `app.js`, update the dashboard:

```bash
kubectl apply -k apps/homelab-dashboard
```

The service must also have its own Ingress and a local DNS record pointing to the Traefik LoadBalancer IP.
